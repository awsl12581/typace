# 自主多卫星轨道仿真

## Goal

把 typace 从太阳系观察器扩展为 KSP 风格的多卫星轨道仿真。卫星从数据目录加载，分别运行在地球轨道和月球轨道，共享同一仿真时钟，并在未被玩家接管时持续自主运行。系统必须使用同一套物理状态支持自主变轨与玩家直接控制，不能为自动驾驶、手动驾驶或画面展示维护平行轨道。

本 Mission 一次性完成这部分架构和实现，不以临时演示、单星特例或只覆盖圆轨道的阶段版本交付。实现范围包括卫星目录、六自由度状态、轨道与姿态传播、主推进和 RCS、燃料、电力、自主飞行计算机、玩家接管、地月转移、轨道维持、交会预警、避碰、再入毁伤、碰撞销毁、Textual 操作界面以及终端和 SDL 两端验证。

## Scope

### 包含

- 加载多颗地球卫星和月球卫星。仓库附带六颗真实卫星的数据，外部目录可以增加卫星、推进器和结构定义。
- 附带目录至少覆盖以下对象与轨道类别：
  - 国际空间站 ISS：地球低轨。
  - GPS BIIR-2 / USA-150：地球中轨。
  - GOES-16：地球同步轨道。
  - Lunar Reconnaissance Orbiter：月球低轨、近极轨。
  - Danuri / KPLO：第二条月球极轨，用于验证同一主天体下的多星运行和交会检测。
  - Queqiao-2：月球高椭圆轨道。
- 真实公开参数优先。每个来源字段记录来源、原始单位、数据历元和转换方法。公开资料没有给出的推进剂、推力、比冲、惯量、迎风面积、阻力系数、热流上限、动压上限、太阳能和电池参数必须标为建模假设。
- 单一场景历元 `scenario_epoch`。每颗卫星可以有自己的数据历元，加载时先传播到场景历元，再创建运行实例。
- 程序运行时完全离线。卫星实例、轨道、结构、推进、电力和来源元数据只从本地 JSON 目录加载；运行期不请求卫星服务、天文服务、URL 或远端星历。
- 面向用户或持久化的内容不得出现绝对路径和个人敏感信息。诊断、日志、UI、事件、测试快照和生成文档只使用目录别名、相对路径、稳定对象 ID 与机构级公开来源，不输出系统用户名、个人姓名、邮箱、主机名、令牌、查询参数或环境变量值。
- 初始轨道允许两种互斥表达：惯性系位置/速度状态向量，或经典开普勒根数。加载后统一转换为 SI 状态向量。
- 地球/月球 patched-conic、中心引力、地球 J2 摄动、地球自转大气中的阻力、有限推力、质量流失和地表碰撞。
- 完整刚体姿态状态：四元数、角速度、惯性张量、反作用轮、RCS 力矩和主发动机机体轴推力。
- 主推进剂与 RCS 推进剂分别核算。燃料耗尽只会停用对应推进系统，不会直接销毁卫星。
- 太阳能发电、电池容量、基础负载、飞控/传感器负载、反作用轮和执行器负载，以及地球或月球遮挡造成的失电。
- 自主飞行计算机支持轨道维持、改变近远点或目标高度、改变倾角、地月转移、返回稳定轨道、受控离轨和自主避碰。
- 玩家可选择并接管任意存活卫星，直接控制姿态、油门、点火和关机。归还控制权后，自主系统从当前真实状态重新规划。
- 所有未被玩家接管的卫星继续后台运行。暂停和时间倍率作用于整个仿真世界。
- 卫星间交会预警、自主避碰和几何碰撞。燃料或电力不足时只报告无法避碰，不得直接修改轨道。
- 三类销毁条件：超过最大动压、超过最大对流热流或撞击地表。卫星销毁后从活动仿真和控制集合中移除，并在当前会话保留带时间、位置和原因的事件记录。
- 同一 Textual 应用在终端和 SDL3 + OpenGL 后端运行。保证 64 颗卫星并行仿真；超过 64 颗允许加载，但不承诺性能。

### 数据可信度

太阳系和卫星使用真实尺度，但不是天文历表级仿真。附带数据必须明确区分：

- `observed`：来自公开任务资料、机构数据或经过记录的轨道数据。
- `derived`：由已引用数据按文档公式换算得到。
- `assumed`：为仿真补齐的工程参数或初始角度。

每个数据文件必须有稳定 ID、显示名称、来源列表和逐字段 provenance。附带来源只记录机构名称、公开文档标题、发布日期和清理后的公开 URL，不记录作者姓名、邮箱、账户名或 URL 查询参数。不能把假设值描述为真实测量。历史或当前状态无法在同一场景历元成立时，目录应说明该实例是以真实航天器参数构造的仿真场景，不声称重现该时刻的真实在轨状态。

## Non-goals

- 不实现联机、通信链路、指令传播延迟、地面站或 CommNet。
- 不下载实时卫星状态、在线 TLE、IERS 表、SPICE kernel、星历或其他运行时数据。
- 不实现任务系统、教程、成就或剧情目标。
- 不实现保存、自动保存、恢复、存档迁移或存档兼容层。
- 不实现对接、分离、载荷部署、分级、VAB 或部件编辑器。
- 不实现 TLE/SGP4。TLE 可以作为来源，但必须离线转换为有明确历元与参考系的状态向量后写入目录。
- 不实现 N 体摄动、太阳辐射压、潮汐、相对论修正、地球高阶重力场或月球非球形重力场。
- 不支持需要圆形限制性三体模型才能正确维持的 NRHO、晕轨道或拉格朗日点轨道。
- 不为本 Mission 预留未使用的网络、任务或存档接口。

## Design

### 架构边界

代码按职责拆分，依赖方向保持单向：

```text
JSON catalogs
    -> catalog validation and epoch normalization
    -> immutable satellite definitions
    -> mutable satellite instances
    -> physics propagation and event detection
    -> navigation and objective management
    -> trajectory planning and guidance
    -> control, execution and safety supervision
    -> world snapshot
    -> celestial renderer and Textual panels
    -> terminal or SDL backend
```

建议的模块边界如下，实施时允许按现有命名小幅调整，但职责不得混合：

- `typace/config/physics.py`：跨模块物理常数、积分容差、事件阈值及来源说明。
- `typace/config/simulation.py`：固定更新周期、时间倍率、预测窗口和 64 星性能预算。
- `typace/config/ui.py`：现有字体与窗口默认值。
- `typace/satellites/catalog.py`：目录 schema、严格校验、来源元数据、合并和历元归一化。
- `typace/satellites/definition.py`：不可变卫星、结构、推进器和电力定义。
- `typace/satellites/state.py`：位置、速度、质量、姿态、资源、控制权和生命周期状态。
- `typace/satellites/commands.py`：玩家与自主系统共用的领域命令、执行器请求和明确的成功/拒绝结果。
- `typace/satellites/data/`：附带清单、卫星、推进器与结构 JSON。
- `typace/physics/frames.py`：惯性系、主天体相对系、轨道局部系和机体系转换。
- `typace/physics/elements.py`：状态向量和轨道根数转换。
- `typace/physics/kepler.py`：二体解析传播和轨道派生量。
- `typace/physics/lambert.py`：把领域输入转换为 `lamberthub.izzo2015` 的零圈求解调用，再把结果转换回 SI 速度向量；不实现第二套 Lambert 算法。
- `typace/physics/soi.py`：SOI 判定和连续参考系切换。
- `typace/physics/forces.py`：中心引力、J2、阻力和推力。
- `typace/physics/attitude.py`：四元数和刚体角速度传播。
- `typace/physics/actuators.py`：主发动机、RCS、反作用轮、执行器限制和推进剂流量。
- `typace/physics/propagation.py`：平动与转动积分、子步调度和事件根定位。
- `typace/physics/environment.py`：分层大气、天体自转、日照、遮挡、动压和热流。
- `typace/simulation/world.py`：单一世界时钟、多卫星实例和确定性更新顺序。
- `typace/simulation/events.py`：事件根定位、销毁事件和同刻事件排序。
- `typace/flight/navigation.py`：从世界快照生成确定性的理想导航解，不读取 UI 状态。
- `typace/flight/objectives.py`：高层目标、优先级、完成条件和失败原因；这里的 objective 是单颗卫星的飞行目标，不是玩家任务系统。
- `typace/flight/planning/orbit.py`：轨道维持、高度、近远点和倾角机动计划。
- `typace/flight/planning/transfer.py`：双向地月转移、捕获、返回稳定轨道和受控离轨计划。
- `typace/flight/planning/avoidance.py`：把交会风险转换为受资源与近地点约束的避碰计划。
- `typace/flight/guidance.py`：把当前计划转换为姿态目标、点火窗口和油门请求。
- `typace/flight/attitude_control.py`：把姿态误差转换为反作用轮或 RCS 力矩请求。
- `typace/flight/execution.py`：按计划状态和控制权提交执行器请求，管理点火开始、完成、中止与重规划。
- `typace/flight/safety.py`：碰撞、结构、热和电力安全监督，对自动和手动请求执行同一套拒绝或中止规则。
- `typace/flight/autopilot.py`：只编排导航、目标、规划、制导、控制、执行和安全模块，不包含轨道公式、PID 计算或资源扣除。
- `typace/flight/manual.py`：把玩家三轴、姿态模式、油门和点火输入转换为与自动驾驶相同的执行器请求。
- `typace/flight/conjunction.py`：交会候选筛选、精化和唯一让行方选择；碰撞根定位由仿真事件模块处理。
- `typace/celestial/rendering.py`：在现有天体与轨道上增加卫星、预测轨迹和状态标记，只消费快照，不运行物理或规划。
- `typace/application.py`：组合 Textual 视图与控制面板，不承担动力学计算。

现有 `typace/config.py` 必须上位替换为 `typace/config/` 包。迁移全部调用方后删除旧模块，不保留别名、兼容文件或双来源。`typace.ui` 的公共接口仍然只有 `run` 和 `WindowOptions`；物理、目录和业务对象不得从 wrapper 重新导出。

模块按变化原因划分，不按每个类或每条公式拆文件。一个模块可以包含若干紧密相关的纯函数和数据类；不得为只有一个实现的组件预先创建抽象基类、工厂、注册表或依赖注入容器。确有第二个生产实现时，再从已有调用代码中提取最小协议。

### 接口心智模型

公共接口使用领域动作和领域对象。调用方应能直接表达“加载目录、创建世界、推进时间、提交命令、读取快照”，不需要先查服务、拼装字典或理解内部积分器：

```python
catalog = load_catalog(paths)
world = SimulationWorld.from_catalog(catalog, scenario_epoch)
result = world.submit(satellite_id, SetOrbitAltitude(altitude_m))
snapshot = world.step(duration_s)
```

接口遵守以下规则：

- `load_catalog(paths)` 接受 `Sequence[Path]`，返回完成合并、校验和单位转换的 `SatelliteCatalog`；错误以一个带 JSON 字段路径列表的 `CatalogError` 返回给启动层。文件位置只显示目录别名和相对路径，不暴露解析后的绝对路径。
- `SimulationWorld.from_catalog(...)` 是创建运行实例的唯一入口。`step(duration_s)` 推进世界并返回不可变 `WorldSnapshot`；调用方不能取得可写的内部卫星集合。
- `world.submit(satellite_id, command)` 是自动驾驶面板、手动面板和按键的共同命令入口，返回包含接受状态和原因的 `CommandResult`。拒绝是正常结果，不使用异常表示燃料不足、电力不足或目标不可达。
- 轨道规划函数接收 `NavigationSolution`、明确的目标和资源约束，返回 `FlightPlan` 或 `PlanningFailure`。不得接受整个应用对象、Textual widget 或松散字典。
- `guidance`、`attitude_control` 和 `execution` 依次接收上一步的具名数据类。自动驾驶编排器不得跳过这些层直接修改状态。
- 手动控制跳过高层目标与轨迹规划，但不跳过安全监督、执行器限制、推进剂、电力或传播器。其直接性指玩家命令立即成为当前控制请求，不代表直接写位置、速度或姿态。
- 查询方法使用自然领域名称和 SI 单位后缀，例如 `orbit_for(satellite_id)`、`remaining_propellant_kg` 和 `battery_energy_j`。布尔方法回答单一问题，例如 `can_start_burn(...) -> bool`。
- 可预期业务失败使用具名结果；目录损坏使用 `CatalogError`；程序缺陷和非有限状态由仿真故障边界捕获并终止对应卫星。不要用一个通用 `Result[Any]` 隐藏不同错误语义。

### Python 标准库与第三方包

实现先使用 Python 标准库和仓库现有依赖：

- `dataclasses`、`enum` 和 `typing` 定义不可变命令、状态、计划和事件，不引入只为模型声明服务的框架。
- `json` 和 `pathlib` 负责目录读取与路径；JSON 边界自行执行严格字段与范围校验。
- `argparse` 处理可重复的 `--satellite-catalog`；`collections.deque` 管理有界命令与事件队列；`statistics` 计算性能样本的百分位输入统计。
- 已有 `numpy` 负责向量、矩阵、四元数和批量数值计算；已有 Textual、pyte、PySDL3、ModernGL 和 FreeType 继续承担各自现有边界。

根目录 `requirements.txt` 增加并直接使用以下运行时依赖；这些版本已经在 Conda `typace` 的 Python 3.14.7 环境中成功导入：

- `astropy>=8,<9`：`astropy.time.Time` 统一解析 RFC 3339 历元、UTC 和时间差，`astropy.units` 负责目录边界的单位校验与 SI 转换，`astropy.constants` 提供其覆盖且精度合适的基础常数。标准参考系转换在 Astropy 已完整覆盖时使用 `astropy.coordinates`；项目只实现 Astropy 没有覆盖的主天体局部轨道系、机体系和 patched-conic 平移。初始化时固定 `iers.conf.auto_download = False`、`iers.conf.iers_degraded_accuracy = "error"`，并使用 `solar_system_ephemeris.set("builtin")`，禁止 Astropy 访问网络、隐式下载数据或静默使用降级精度。需要的转换超出内置数据能力时，目录加载明确失败。
- `lamberthub>=1,<2`：生产路径固定调用 `lamberthub.izzo2015`，并固定 `M=0`；low/high path、顺行/逆行和指定飞行时间由领域命令明确给出。typace 只保留领域适配、输入约束和失败映射，不复制 Izzo 或其他 Lambert 实现，也不允许在运行时选择求解算法。
- `scipy>=1.18,<2`：使用 `scipy.optimize` 的标量/多变量求根和有界一维最小化，处理有限燃烧修正、交会最近时刻和事件精化。生产代码不保留自制 Newton、二分、通用最小化或失败 fallback。

上位替代按能力边界执行：Astropy 完整替代自制时间解析、单位系统和它支持的标准参考系变换；lamberthub 完整替代自制 Lambert 求解；SciPy 完整替代通用求根与最小化。旧实现、备用实现、兼容包装和“第三方失败后走自制算法”的分支必须删除。薄适配层只能转换本项目的具名领域类型、固定参数和错误语义，不能复制算法。测试可以用文档公式或公开基准做独立断言，但不得把测试参考实现接入生产路径。

lamberthub `1.0.0` 传递依赖 Numba。typace 不直接导入 Numba，也不建立自己的 JIT 路径；依赖的安装和版本解析由 lamberthub 声明负责。本 Mission 仍不增加 Pydantic、poliastro、sgp4、Skyfield 或 SpiceyPy：标准库数据类和显式边界校验足以覆盖固定 JSON schema；poliastro 会与共享世界状态和传播器形成重叠；TLE/SGP4 与天文历表级仿真已明确排除。

### 目录与加载

应用增加可重复参数：

```text
--satellite-catalog PATH
```

不指定参数时加载仓库附带清单。每个额外路径可以是单个 JSON 文件或一个目录；目录内按文件名稳定排序加载。附带目录与外部目录使用同一解析器和校验器。所有定义 ID 全局唯一，重复 ID 立即报错并拒绝启动，禁止静默覆盖。派生对象使用新 ID，并通过 `derived_from` 指向来源定义。

`--satellite-catalog` 只接受本地文件系统路径，不接受 `http:`、`https:`、`ftp:`、`data:` 或其他 URI。调用方可以传入相对或绝对本地路径，但加载器立即为每个根目录分配不含用户名的稳定别名；后续诊断和状态只保留别名下的相对文件名，不保存或输出绝对路径。JSON 中的来源 URL 仅作为不可执行的 provenance 字符串保存和显示，加载器不得访问它；显示前去除 userinfo、query 和 fragment。运行时的卫星状态只来自已加载 JSON 和之后的本地物理传播；不得用网络结果补齐、刷新或覆盖字段。

场景清单包含：

- schema 版本，仅用于目录格式校验，不是存档版本。
- `scenario_epoch`，RFC 3339 UTC 时间。
- 引用的卫星定义 ID。
- 可选外部目录来源说明。

卫星定义至少包含：

- `id`、名称、运营方、主天体 ID、来源和逐字段 provenance。
- 初始状态：`epoch`、参考系以及状态向量或六个开普勒根数，二者严格互斥。
- 干质量、主推进剂质量、RCS 推进剂质量、质心参考下的对角惯性张量。
- 碰撞半径、迎风面积、阻力系数和参考鼻锥半径。
- 主发动机推力、比冲、最小油门和机体推力轴。
- RCS 总推力、比冲和最大力矩。
- 反作用轮最大力矩和最大储存角动量。
- 太阳能板面积、效率、机体法向，电池容量、初始电量和分项功耗。
- 最大允许动压和最大允许对流热流。
- 自主策略：目标轨道、容差、最低推进剂储备、避碰安全半径和允许的命令集合。

长度、质量、时间、速度、力、力矩、能量和角度在运行模型中分别使用 m、kg、s、m/s、N、N·m、J 和 rad。JSON 字段名必须带单位后缀，角度输入使用 `_deg` 并在边界转换为 rad。不得在业务代码中重复单位换算。

### 初始状态归一化

状态向量输入直接给出主天体相对惯性系中的

\[
\mathbf y_0=(\mathbf r_0,\mathbf v_0,m_0,q_0,\boldsymbol\omega_0),
\]

其中 \(\mathbf r\) 的单位是 m，\(\mathbf v\) 是 m/s，\(m\) 是 kg，\(q\) 是单位四元数，\(\boldsymbol\omega\) 是机体系 rad/s。

开普勒输入为半长轴 \(a\)、偏心率 \(e\)、倾角 \(i\)、升交点赤经 \(\Omega\)、近地点幅角 \(\omega\) 和平近点角 \(M\)。加载器先解

\[
M=E-e\sin E,
\]

再求真近点角

\[
\nu=2\operatorname{atan2}\left(\sqrt{1+e}\sin\frac E2,
\sqrt{1-e}\cos\frac E2\right).
\]

半通径与轨道平面状态为

\[
p=a(1-e^2),\qquad r=\frac p{1+e\cos\nu},
\]

\[
\mathbf r_{pf}=r(\cos\nu,\sin\nu,0),
\]

\[
\mathbf v_{pf}=\sqrt{\frac\mu p}(-\sin\nu,e+\cos\nu,0).
\]

通过

\[
\mathbf Q=R_3(\Omega)R_1(i)R_3(\omega)
\]

转换到主天体相对惯性系：\(\mathbf r=\mathbf Q\mathbf r_{pf}\)，\(\mathbf v=\mathbf Q\mathbf v_{pf}\)。

每颗卫星从自己的数据历元传播到 `scenario_epoch`。传播使用本 Mission 的同一力模型；如果来源只足以支持二体回推，provenance 必须标明这个近似。时间归一化完成后才允许创建 `SatelliteInstance`。

### 平动物理

卫星的平动方程为

\[
\dot{\mathbf r}=\mathbf v,
\]

\[
\dot{\mathbf v}=\mathbf a_g+\mathbf a_{J2}+\mathbf a_d+\mathbf a_T.
\]

中心引力为

\[
\mathbf a_g=-\mu\frac{\mathbf r}{r^3},\qquad \mu=GM.
\]

\(G\)、天体质量和派生 \(\mu\) 必须有唯一配置来源；如果目录直接提供权威 \(\mu\)，不得同时从另一个不同质量值派生并形成双来源。

地球 J2 摄动为

\[
\mathbf a_{J2}=\frac{3J_2\mu R^2}{2r^5}
\begin{bmatrix}
x(5z^2/r^2-1)\\
y(5z^2/r^2-1)\\
z(5z^2/r^2-3)
\end{bmatrix}.
\]

这里 \(R\) 是地球参考赤道半径，\(z\) 沿地球自转轴。J2 只对地球主天体启用。实现必须用测试验证升交点长期进动方向与一阶理论值一致：

\[
\dot\Omega=-\frac{3}{2}J_2n\left(\frac Rp\right)^2\cos i,
\qquad n=\sqrt{\frac\mu{a^3}}.
\]

地球大气采用可配置的分层指数模型，而不是单一海平面尺度高度：

\[
\rho(h)=\rho_i\exp\left(-\frac{h-h_i}{H_i}\right),
\qquad h_i\le h<h_{i+1}.
\]

密度表覆盖低层大气到至少 1000 km，并注明采用的标准大气或工程近似来源及适用范围。大气随地球自转，空气相对速度为

\[
\mathbf v_{rel}=\mathbf v-\boldsymbol\omega_E\times\mathbf r.
\]

阻力为

\[
\mathbf a_d=-\frac12\rho C_D\frac A m
|\mathbf v_{rel}|\mathbf v_{rel}.
\]

迎风面积在本 Mission 中使用目录给出的等效面积，不实现随姿态变化的复杂气动外形。月球无大气，\(\mathbf a_d=0\)。

主发动机推力为

\[
\mathbf a_T=\frac{T\eta}{m}\,R(q)\hat{\mathbf t}_b,
\]

其中 \(T\) 是额定推力，\(\eta\in[0,1]\) 是油门，\(R(q)\) 把机体系推力轴 \(\hat{\mathbf t}_b\) 转到惯性系。推进剂质量流率为

\[
\dot m_p=-\frac{T\eta}{I_{sp}g_0}.
\]

可用理想速度增量使用齐奥尔科夫斯基火箭方程校验：

\[
\Delta v=I_{sp}g_0\ln\frac{m_0}{m_f}.
\]

质量始终为干质量、主推进剂和 RCS 推进剂之和。任何一步不得把推进剂积分为负数；最后一个子步按剩余推进剂截断推力时长。

### Patched-conic 与参考系切换

子天体的影响球半径为

\[
r_{SOI}=a\left(\frac mM\right)^{2/5}.
\]

卫星使用包含其惯性位置的最小地月 SOI 作为当前主天体：月球 SOI 内以月球为主天体，其余位置以地球为主天体。该 Mission 不创建日心卫星；越过地球作用域的轨迹报告为超出支持范围。地月转移切换主天体时保持惯性位置和速度连续：

\[
\mathbf r_{new}=\mathbf r_{old}+\mathbf R_{old}-\mathbf R_{new},
\]

\[
\mathbf v_{new}=\mathbf v_{old}+\mathbf V_{old}-\mathbf V_{new}.
\]

SOI 检查必须在积分子步内执行，并用事件根定位把切换时间收敛到配置容差内，不能只在一帧结束时跳变。

### 数值传播

统一数值传播路径使用项目内固定步长 RK4，同时积分平动、姿态、角速度、电量和推进剂。SciPy 只提供有限燃烧修正、最近时刻最小化和事件精化，不拥有或复制传播状态。子步上限取以下限制的最小值：

- 当前轨道周期的配置分数。
- 推力开启时允许的最大燃烧步长。
- 大气层内按密度尺度高度和径向速度推导的穿层步长。
- 距 SOI、地表、热流、动压和碰撞事件的预计到达时间。
- 姿态角速度与执行器控制周期限制。

只有同时满足以下条件时才允许用解析开普勒传播：无推力、无大气阻力、无 J2、不会在该步内接近 SOI 或地表、没有待处理交会事件。地球卫星因为 J2 常开，正常情况下使用数值传播；月球巡航可走解析路径。

现有离散时间倍率仍然可用，但显示的选择倍率和实际使用的有效倍率必须分开。有效倍率受燃烧、姿态转向、大气层、SOI、交会和事件步长限制，只能低于或等于选择倍率。高倍率不得跳过点火窗口、推进剂耗尽、失电、碰撞或毁伤事件；限制生效时 UI 显示实际倍率和限制原因。

每个仿真 tick 按稳定 ID 排序更新卫星，先冻结世界快照，再分别计算导引和控制，最后提交全部新状态，避免列表顺序造成结果差异。自主规划可以低频运行，物理积分仍按固定世界时钟运行。渲染只读取 tick 完成后的不可变快照。

### 姿态与执行器

姿态使用单位四元数 \(q\) 和机体系角速度 \(\boldsymbol\omega\)：

\[
\dot q=\frac12 q\otimes(0,\boldsymbol\omega).
\]

每个积分子步后归一化四元数。刚体角动量方程为

\[
\mathbf I\dot{\boldsymbol\omega}
=\boldsymbol\tau-\boldsymbol\omega\times(\mathbf I\boldsymbol\omega).
\]

反作用轮控制力矩受 \(\tau_{rw,max}\) 限制，储存角动量满足

\[
\dot{\mathbf H}_{rw}=-\boldsymbol\tau_{rw},
\qquad |H_{rw,k}|\le H_{rw,max,k}.
\]

饱和轴不能继续提供同方向轮力矩。自主系统应使用 RCS 卸载轮动量；RCS 按成对推力器的等效力矩工作并消耗独立推进剂：

\[
\dot m_{rcs}=-\frac{T_{rcs}\eta_{rcs}}{I_{sp,rcs}g_0}.
\]

姿态控制器使用带饱和与 anti-windup 的 PID 或等价反馈律。姿态误差由目标四元数与当前四元数计算，不允许瞬时改变朝向。主发动机只能沿真实机体推力轴工作；未对准时会产生余弦损失。

### 电力与遮挡

太阳能输入为

\[
P_{solar}=S_0\left(\frac{AU}{d_\odot}\right)^2
A_{panel}\eta_{panel}\max(0,\hat n_{panel}\cdot\hat s)\chi,
\]

其中 \(\chi\) 在无遮挡时为 1，被地球或月球完全遮挡时为 0。遮挡通过太阳到卫星的线段与天体球体求交判定；本 Mission 不实现半影。电池能量为

\[
\dot E=P_{solar}-P_{base}-P_{computer}-P_{sensor}-P_{actuator},
\qquad 0\le E\le E_{max}.
\]

功耗按当前工作状态叠加，不能只显示预算而不实际扣除。电量降到配置的 brownout 阈值时进入 `POWER_SAFE`：关闭推进、规划和非必要传感器，只保留被动传播与允许的最低负载。电量恢复到带回差的恢复阈值后，飞控重新初始化导航估计并重新规划；不得续跑失电前尚未验证的点火命令。

导航采用确定性的理想状态估计：供电正常时，飞控可读取当前仿真状态，不加入测量噪声、滤波器偏差或传感器故障。传感器功耗仍按工作状态扣除；进入 `POWER_SAFE` 后导航数据冻结，恢复供电时从当前真实状态重新初始化。这样保留导航、制导、控制的模块边界，但不把本 Mission 扩张成传感器误差仿真。

### 控制权与自主状态机

每颗卫星独立保存控制权、命令队列和执行状态。控制权只有：

- `AUTONOMOUS`：飞行计算机可以规划并控制执行器。
- `MANUAL`：玩家直接控制姿态目标、油门、点火和关机；自主系统停止发出执行器命令，但继续监测安全事件。
- `POWER_SAFE`：电力不足，自动和手动执行器命令均无效。
- `DESTROYED`：终态，实例从活动集合移除。

玩家接管时取消尚未开始的自主执行器命令，并冻结其高层目标，不改变位置、速度、姿态或燃料。归还自主控制后，旧的低层燃烧步骤作废；系统从当前状态重新计算轨道、资源与可达性，再生成新计划。

自主命令包括：

- 维持目录声明的目标轨道容差。
- 设置目标近地点、远地点或圆轨道高度。
- 设置目标倾角。
- 从地球轨道转移到月球轨道，或从月球返回地球稳定轨道。
- 受控离轨，目标是进入大气层并最终销毁。
- 避碰机动。

优先级固定为：立即碰撞避免、结构/热/电力安全、正在执行且仍安全的有限燃烧、用户高层命令、轨道维持。玩家处于 `MANUAL` 时只保留告警，不得让自动控制偷偷改写姿态或油门。

轨道维持使用带滞回的容差带，避免在阈值附近反复点火。变高/降轨使用 Hohmann 初值：

\[
\Delta v_1=\sqrt{\frac\mu{r_1}}
\left(\sqrt{\frac{2r_2}{r_1+r_2}}-1\right),
\]

\[
\Delta v_2=\sqrt{\frac\mu{r_2}}
\left(1-\sqrt{\frac{2r_1}{r_1+r_2}}\right),
\]

\[
t_H=\pi\sqrt{\frac{(r_1+r_2)^3}{8\mu}}.
\]

纯平面变化速度增量为

\[
\Delta v_i=2v\sin\frac{|\Delta i|}{2}.
\]

地月转移采用 patched-conic：调用 `lamberthub.izzo2015` 并固定 `M=0` 解算地心出发弧，进入月球 SOI 后切换月心状态，再规划有限时长捕获燃烧。调用明确指定飞行时间、顺行/逆行和 low/high path；不可达、燃料不足、点火窗口已经过去或有限推力迭代不收敛时必须返回明确失败，不得切换求解算法或自制求解器，也不得退化为瞬时改写状态。

规划得到的脉冲 \(\Delta v\) 只是初值。执行前必须用真实推力、质量流、姿态转向时间以及同一力模型正向积分有限燃烧，通过数值求根修正燃烧时长或开始时刻，直到目标轨道残差进入配置容差。预测和真实执行必须调用同一传播器与力函数。

### 手动控制和 Textual UI

应用增加卫星列表、遥测面板、自动驾驶面板和手动控制面板。它们使用 Textual 原生组件、焦点、按键、事件和 CSS，不创建新的 Canvas、Cell、组件树或布局引擎。

玩家可以：

- 在存活卫星间切换活动卫星并聚焦其位置或轨道。
- 查看主天体、位置/速度、近远点、倾角、周期、姿态误差、主推进剂、RCS 推进剂、电量、发电/负载、控制权、计划、交会告警和最近事件。
- 向自主系统提交目标高度、近远点、倾角、目标天体、返回稳定轨道或受控离轨命令。
- 接管/归还控制权。
- 直接发出机体系俯仰、偏航和滚转力矩命令，也可以选择顺行、逆行、径向外/内、法向正/负和惯性保持作为姿态目标。
- 手动调节油门，点火或关机，使用 RCS 姿态控制，并看到燃料或电力不足的拒绝原因。

手动按键与面板按钮调用同一命令接口。UI 不直接修改卫星字段。终端与 SDL 后端运行同一应用和同一控制逻辑；SDL 驱动只负责窗口生命周期、输入适配和绘制。

渲染层在现有星体系统上增加卫星当前位置、活动卫星轨道、计划轨迹、推力状态、交会告警和销毁闪现。低倍率下使用字体可用的稳定几何符号，近距离显示朝向；碰撞标记和卫星命中映射必须支持鼠标选择。所有固定格式元素使用稳定尺寸，不能因状态文本变化推动地图布局。

### 交会、避碰与碰撞

交会检测只对同一主天体下的存活卫星配对。64 星以内可以使用确定性的 \(O(n^2)\) 配对；不得为未证明的规模提前加入空间数据库。先用相对直线近似筛选预测窗口内的最近时刻：

\[
t_{ca}=\operatorname{clamp}\left(
-\frac{\mathbf r_{rel}\cdot\mathbf v_{rel}}
{|\mathbf v_{rel}|^2},0,T_h\right),
\]

\[
d_{ca}=|\mathbf r_{rel}+t_{ca}\mathbf v_{rel}|.
\]

候选对再用同一传播器分别传播到 \(t_{ca}\)，并在附近做一维时间最小化。若预测距离低于目录安全半径，双方飞行计算机按稳定 ID 决定唯一让行方，避免双方对称机动。避碰计划必须满足剩余燃料、电力、姿态转向时间和不降低近地点到危险范围等约束。

真实碰撞判据为

\[
|\mathbf r_1-\mathbf r_2|\le R_{c,1}+R_{c,2}.
\]

在一个子步内跨过碰撞边界时用根定位求事件时刻。碰撞双方同时销毁并记录同一事件 ID。本 Mission 不实现对接或弹性碰撞。

### 再入、热流与销毁

动压为

\[
q_d=\frac12\rho|\mathbf v_{rel}|^2.
\]

对流驻点热流使用 Sutton-Graves 工程关系：

\[
\dot q_s=k\sqrt{\frac\rho{R_n}}|\mathbf v_{rel}|^3.
\]

常数 \(k\) 的单位、气体体系、来源和适用速度范围必须在 `config/physics.py` 定义处说明。目录中的 `max_dynamic_pressure_pa` 和 `max_heat_flux_w_m2` 分别与上述结果比较。达到任一上限即在事件根定位后的时刻销毁。

地表撞击满足

\[
|\mathbf r|\le R_{body}.
\]

本 Mission 的卫星没有软着陆能力，接触地球或月球表面一律销毁。进入大气层本身不是销毁条件。燃料归零也不是销毁条件；卫星会继续受引力、J2 和阻力作用，直到稳定留轨或满足某个毁伤判据。

销毁操作从活动仿真、控制和交会集合中原子移除实例，并追加只读 `DestructionEvent`。同一 tick 的 UI 快照不能同时把卫星显示为存活和销毁。

### 配置、来源与代码约束

物理常数、时间步、容差、预测窗口、功率阈值、控制增益默认值和安全倍率不得以内联魔法值出现。跨模块值按物理、仿真和 UI 领域分别放入 `typace/config/`；只服务一个实现的值留在该模块，以具名常量表示。每个物理量定义必须写明单位、来源、适用范围和精度依据，派生值从基础常量计算。

复杂 `if`、`elif` 和 `while` 条件抽成返回 `bool`、无副作用且名称表达领域问题的谓词。所有新增或修改的公开接口完整标注类型。不得用 `Any`、`type: ignore`、关闭检查或降低 Pylance/Pyright 等级掩盖错误。

所有 Python 命令使用现有 Conda `typace` 环境。新增与修改的 Python 文件使用 Black。Pyright CLI 是补充验证，报告中必须与 Pylance 编辑器诊断区分。依赖变更只写入根目录 `requirements.txt`，不得新建第二套环境文件；新增依赖必须有实际生产调用方和对应测试。

### 确定性、性能与故障处理

同一目录、场景历元、命令序列和时间步必须产生可重复结果。卫星集合迭代、交会配对、避碰让行和同刻事件排序都使用稳定 ID。渲染帧率不能反向决定物理步长。

在项目默认 SDL 窗口和设计尺寸下，64 颗卫星、30 Hz UI、1 倍时间倍率连续运行时，物理、自主和交会更新合计的第 95 百分位耗时不得超过 20 ms，为现有约 5-7 ms 的场景渲染和事件循环保留余量。性能测试必须使用真实传播、控制和交会路径，不得 mock 核心计算。最高选择倍率下还必须保持 UI 可交互；允许有效倍率因安全步长降低，但不能丢失卫星或事件。

目录错误在创建世界前一次性报告，包含安全的目录别名、相对文件名、对象 ID 和 JSON 字段路径。运行期的规划失败、电力不足、燃料不足、执行器饱和和无法避碰是可观察状态，不得抛出导致应用退出的异常。NaN、非有限状态、负质量或非法四元数属于仿真故障，必须终止对应卫星、记录明确原因，并保持其他卫星运行。异常链在进入日志、UI 或测试快照前经过同一净化函数，删除绝对路径和敏感字段；不得直接显示第三方异常的原始 `repr`。

- 现有只展示天体的调用方和测试迁移到新的世界快照入口；不得保留新旧两条生产渲染路径。

## Security

外部目录只作为本地 JSON 数据解析，不执行代码，不解析对象钩子，不展开任意路径引用，也不访问 JSON 中出现的 URL。目录文件大小、对象数量、字符串长度和数值范围必须有具名限制；超过限制时拒绝加载。错误信息不得回显文件中与诊断无关的大段内容。生产代码不得包含卫星数据、IERS 表或星历的 HTTP 客户端、在线 provider 或自动下载分支。

所有对外文本共用一个净化边界。禁止输出绝对路径、用户主目录、系统账户名、个人姓名、邮箱、主机名、IP、访问令牌、密钥、环境变量值和 URL userinfo/query/fragment。仓库附带 JSON、文档和测试数据不得包含真实个人信息；需要验证净化时只使用显式虚构占位值。机构名、航天器名、稳定对象 ID、公开文档标题和无敏感部分的公共来源 URL 不视为个人敏感信息。


不提供关闭新世界模型的 feature flag，也不保留旧观察器作为回退实现。Git 可以回滚整个提交序列；运行时不维护双路径。

## Acceptance Criteria

### 目录与数据

1. 附带目录通过严格 schema 校验并加载六颗指定卫星；运行代码中没有硬编码卫星实例。
2. `--satellite-catalog` 可重复使用，文件和目录都可加载；重复 ID、未知引用、单位缺失、非法范围、同时提供状态向量和根数、或两者都未提供时启动失败并给出字段路径。
3. 每个附带字段可追溯为 `observed`、`derived` 或 `assumed`，并有来源、历元和单位。抽样测试核对至少一颗地球卫星和一颗月球卫星的原始数据到 SI 状态转换。
4. 不同数据历元的卫星在创建世界前统一传播到 `scenario_epoch`，相同输入重复加载得到逐分量一致的状态。
5. 在禁止网络连接的进程中，附带目录和外部本地 JSON 可以完成加载、历元归一化、世界创建和持续传播，且没有任何 DNS、socket 或 HTTP 尝试。`--satellite-catalog` 拒绝 URI；provenance URL 不会被访问；Astropy 使用内置数据并关闭 IERS 自动下载。

### 轨道与数值物理

6. 开普勒根数与状态向量往返在声明容差内；圆轨道、偏心轨道、赤道轨道和极轨不产生 NaN 或未定义角度泄漏。
7. 纯二体无推力测试运行至少 100 个轨道周期，比机械能和角动量误差不超过规格中基于步长测得并固定的容差；解析传播一周期回到初始状态容差内。
8. 地球 J2 测试的升交点进动方向正确，速率与一阶公式的相对误差处于声明容差内；关闭 J2 后该长期漂移消失。
9. 地球分层大气密度在每个分层边界连续，随高度非增；同一 LEO 卫星启用阻力后半长轴长期下降，关闭阻力后不下降。
10. 月球卫星不受地球 J2 或大气阻力；地球与月球 SOI 切换前后的惯性位置和速度连续。
11. RK4 子步跨越 SOI、地表、动压、热流或碰撞边界时，事件时间收敛到配置容差，不发生穿透后再纠正。
12. 各档选择倍率均可使用；安全限制生效时有效倍率不超过选择倍率并显示原因。最高选择倍率下不会跳过点火、燃料耗尽、失电、碰撞或毁伤事件。

### 推进、姿态和资源

13. 有限燃烧同时更新位置、速度和质量；燃料消耗符合 \(\dot m=T/(I_{sp}g_0)\)，积分结果与火箭方程预算在声明容差内。
14. 主推进剂耗尽后主发动机推力为零，RCS 仍可在其推进剂和电力允许时工作；任一推进剂都不会变成负数。
15. 姿态四元数长期保持归一，角动量方程、最大轮力矩、轮动量饱和和 RCS 卸载均有独立测试。主发动机只沿实际机体轴施力，未对准会产生可测的余弦损失。
16. 日照、地球遮挡和月球遮挡测试给出正确发电状态；电池能量守恒且限制在 \([0,E_{max}]\)。失电进入 `POWER_SAFE`，执行器停止，轨道仍继续传播；恢复供电后重新规划。

### 自主与手动控制

17. 六颗卫星在无人操作时并行运行，各自维护计划、姿态、燃料和电力；切换活动卫星不改变其他卫星的控制状态。
18. 自主轨道维持能在配置容差外规划并执行有限燃烧，在回到滞回带内后停止修正；燃料不足时报告不可达且不修改状态。
19. 高度/近远点、倾角、地球到月球、月球到地球、返回稳定轨道和受控离轨命令均完成从规划、姿态对准、有限燃烧、SOI 切换到结果校验的闭环。
20. 地月转移预测与实际执行使用同一传播器。标准场景能进入目标月球轨道；不可达或燃料不足场景明确失败，不产生瞬移、免费 \(\Delta v\) 或负燃料。
21. 玩家接管后可以直接施加俯仰、偏航和滚转力矩，改变姿态目标、油门和点火状态；自主系统不覆盖这些命令。归还后旧低层步骤废弃，并从接管后的真实状态重新规划。
22. 手动和自主控制消耗相同燃料与电力，调用相同执行器和传播路径。测试禁止通过直接写速度、轨道根数或燃料结果完成机动。

### 交会与生命周期

23. 交会检测在预测窗口内找出低于安全距离的候选，唯一让行方按稳定 ID 执行避碰。相同初始条件重复运行得到相同计划。
24. 有资源的卫星完成避碰并把预测最近距离提高到安全阈值以上；燃料或电力不足时保留原物理轨迹并持续告警。
25. 两颗卫星的几何距离进入碰撞半径和时，双方在同一事件时刻销毁。不存在对接分支。
26. 超过最大动压、超过最大热流和撞击地球/月球表面分别触发正确销毁原因。进入大气层或燃料耗尽本身不会销毁卫星。
27. 燃料耗尽的低轨卫星在阻力作用下继续衰减并最终触发再入毁伤或撞击；关闭阻力的对照场景不会因燃料为零自行坠毁。
28. 销毁卫星从活动、控制和交会集合原子移除，当前会话的事件记录保留时间、位置、卫星 ID 和原因。

### UI、性能与工程约束

29. Textual 界面可选择和聚焦每颗存活卫星，显示轨道、计划轨迹、姿态、燃料、电力、控制权、交会告警和事件；面板可以提交高层命令并完成手动接管控制。
30. 终端和 SDL 使用同一 Textual 应用和业务逻辑。原生 Textual 组件的键盘、焦点、按钮、输入框、列表、滚轮和鼠标选星均有交互测试。
31. 设置 `TYPACE_TEST_SDL=1` 后，真实 SDL/OpenGL 测试在真实窗口与 GPU 帧缓冲中验证卫星、轨道、告警、面板交互和缩放；headless 或 mock 结果不能代替该项。
32. 64 颗卫星在 30 Hz UI 和 1 倍时间倍率下，物理、自主和交会更新合计的第 95 百分位耗时不超过 20 ms；无状态丢失、跳过后台卫星或按列表顺序变化的结果。
33. `conda run -n typace python -m unittest discover -s tests -v` 全部通过；所有改动 Python 文件通过 Conda `typace` 环境中的 Black；Pyright CLI 对 `app typace samples tests` 报告零错误，并如实标为 CLI 结果。
34. 代码遵守 `AGENTS.md`：复杂控制条件使用具名无副作用谓词，公共接口有类型标注，物理量和阈值有唯一来源、单位、出处和适用范围，UI/SDL wrapper 中没有业务或数值计算。
35. 旧配置模块、旧生产渲染入口和任何临时兼容层在调用方迁移后删除。仓库中不存在新旧卫星状态、传播或控制双实现。
36. 自动驾驶的导航、目标管理、轨迹规划、制导、姿态控制、执行和安全监督可分别做单元测试；`autopilot.py` 只负责按类型化接口编排，源码中不包含轨道公式、PID 计算、执行器资源扣除或 UI 分支。
37. 典型调用代码可以直接完成目录加载、世界创建、时间推进、命令提交和快照读取；自动与手动命令都经过同一个 `world.submit` 生产入口。不存在服务定位器、通用 `dict` 消息、单实现抽象工厂或要求 UI 构造内部规划对象的接口。
38. 根目录 `requirements.txt` 声明 `astropy>=8,<9`、`lamberthub>=1,<2` 和 `scipy>=1.18,<2`，Conda `typace` 的 Python 3.14.7 可以导入并运行。时间、单位、已覆盖参考系、Lambert、通用求根和最小化各自只有一条第三方生产路径；仓库不存在对应自制实现、fallback 或兼容层。三类依赖的正常结果、边界输入和失败映射均有测试；typace 不直接导入 lamberthub 的传递依赖 Numba。
